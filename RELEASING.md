# Releasing

The repo currently ships source only — people clone and build in Xcode. This
is the checklist for putting out a downloadable build when you want one.

Steps 2 and 3 need your Apple Developer credentials, so they can only be run by
you.

## 1. Version

Bump `MARKETING_VERSION` in `app/MiniPetAgents.xcodeproj/project.pbxproj`
(currently `0.1`) and commit.

## 2. Build and sign

An ad-hoc signature is fine for local development but Gatekeeper will block it
on anyone else's Mac. A distributable build needs a Developer ID:

```bash
cd app
xcodebuild -scheme MiniPetAgents -configuration Release \
  -derivedDataPath build \
  CODE_SIGN_IDENTITY="Developer ID Application: YOUR NAME (TEAMID)" \
  CODE_SIGN_STYLE=Manual \
  DEVELOPMENT_TEAM=YOURTEAMID
```

Do **not** commit the team ID back into the project file — a clone should keep
building under "Sign to Run Locally" for everyone else.

## 3. Notarize

Requires an app-specific password stored in your keychain (create one at
appleid.apple.com, then `xcrun notarytool store-credentials`):

```bash
APP="build/Build/Products/Release/Mini Pet Agents.app"
ditto -c -k --keepParent "$APP" MiniPetAgents.zip
xcrun notarytool submit MiniPetAgents.zip --keychain-profile "AC_PASSWORD" --wait
xcrun stapler staple "$APP"
```

Then package it. A plain zip is fine; a DMG is nicer:

```bash
hdiutil create -volname "Mini Pet Agents" -srcfolder "$APP" \
  -ov -format UDZO MiniPetAgents-0.1.dmg
```

Verify the result behaves like a download would:

```bash
spctl -a -vvv -t install "$APP"     # expect: accepted, source=Notarized Developer ID
```

## 4. Publish

```bash
git tag v0.1.0 && git push origin v0.1.0
gh release create v0.1.0 MiniPetAgents-0.1.dmg \
  --title "v0.1.0" --notes-file RELEASE_NOTES.md
```

## 5. Sparkle appcast

Auto-update is wired up but switched off, because `SUEnableAutomaticChecks` is
`false` and no feed exists yet. To turn it on:

1. Generate a signing key once: `./bin/generate_keys` from the Sparkle release
   tools. Put the **public** key in `Info.plist` as `SUPublicEDKey`; keep the
   private key in your keychain.
2. Run `./bin/generate_appcast` against a directory of released archives.
3. Commit the resulting `appcast.xml` to the repo root — `SUFeedURL` already
   points at `raw.githubusercontent.com/.../main/appcast.xml`.
4. Flip `SUEnableAutomaticChecks` to `true` in the same commit.

Until all four are done, leave it off: a feed URL that 404s makes "Check for
Updates…" fail with an error rather than a clean "you're up to date".

## 6. Demo recording

The README's sprite art is generated by `scripts/make-sprite-demo.sh`, but a
recording of the app actually running has to be captured by hand:

Cmd-Shift-5 → Record Selected Portion → drag a box around the pet → record a
pet pacing, a throw bouncing off a screen edge, a hover wave, and a chat turn
finishing. Then:

```bash
./scripts/make-demo-gif.sh ~/Desktop/recording.mov docs/demo.gif
```

and add it near the top of the README. Keep it under about 5MB or GitHub is
slow to load it.
